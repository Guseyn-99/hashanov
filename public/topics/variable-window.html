Как я рассуждаю

Справа добавляю число, пока набираю сумму. Как только суммы хватает, записываю длину и пробую убрать число слева. Каждый раз, пока суммы хватает, проверяю ещё более короткое окно.

Разбор по шагам

Дан список [2, 1, 4, 2]. Найди минимальную длину участка с суммой хотя бы 6. Если такого участка нет, верни 0.

Python 3
def shortest(nums, target):
    left = total = 0
    best = len(nums) + 1
    for right, x in enumerate(nums):
        total += x
        while total >= target:
            best = min(best, right - left + 1)
            total -= nums[left]
            left += 1
    return 0 if best > len(nums) else best

print(shortest([2, 1, 4, 2], 6))

Подвигай границы сам

Сложность и границы

O(n) времени и O(1) памяти. Каждый элемент войдёт в окно один раз и выйдет из него максимум один раз, поэтому while внутри for здесь даёт линейный проход.

С отрицательными числами удаление элемента слева может увеличить сумму. Тогда это правило сжатия уже не гарантирует правильный ответ.

Самостоятельная практика

Напиши longest_under(nums, limit). Все числа положительные, limit ≥ 0. Верни максимальную длину участка с суммой не больше limit. Если подходящих чисел нет, верни 0.

Примеры для проверки

longest_under([2, 1, 2, 4], 5) → 3; longest_under([6], 5) → 0. Подсказка: пока сумма слишком велика, двигай left. Длину обновляй после сжатия.

Подсказка
